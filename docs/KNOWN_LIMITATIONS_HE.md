# מגבלות שחשוב לדעת להסביר

סידור תיקיות ומעבר בדיקות אינם משנים את תקפותם של ניסויים היסטוריים.

| נושא | מה נמצא | המשמעות |
|---|---|---|
| פיצולי זמן | חלק מה־CV וה־holdout משתמשים גם במשחקים מאוחרים מהטורניר הנבדק | דרוש אימון חוזר עם פיצול כרונולוגי לפני טענת דיוק על העתיד |
| בחירת מודל | יש כוונון חוזר על אותן קבוצות הערכה | צריך מבחן סופי שלא שימש לבחירה |
| דירוג קודם | נוסחת שחזור דירוג יצרה 57 ערכים קטנים מ־1 בנתוני הסקירה | צריך לאמת את משמעות סימן השינוי במקור |
| מידע שהיה זמין בזמן | בסיס Elo משתמש בכל הנתונים, וחותמות זמן של שווי שחקנים אינן מאומתות | לא ניתן להבטיח שאין מידע עתידי בפיצ׳רים |
| גרסאות נתונים | `model_dataset` ו־`updated_model_dataset` אינם זהים, ושחזור 05 נתן מספר שורות אחר | לא להחליף קובץ אימון בלי בדיקת מקור וגרסה |
| מחברות | חלקן חלקיות; חיפושים ארוכים ו־API לא הורצו במלואם | קריאת קוד אינה שקולה לאימות כל ניסוי |
| תוצאות 2026 | במאגר נספרו 102 תוצאות, ללא שתי תוצאות הסיום | הנתונים הם צילום מצב המאגר, לא הבטחה לעדכון חי |
| מפתח API | הוסר מהמחברת הנוכחית, אך נשאר בהיסטוריה | בעל המפתח צריך לבטל או להחליף אותו אצל הספק |
| מסך V6 | התוצאה השלמה מכוילת, אך הסתברויות מסך המשחק היחיד מחושבות ב־Poisson הבסיסי | לא לתאר את כל הפלט כאותה התפלגות מכוילת |

## מה כן אפשר לטעון

הקוד מאורגן למסלול קריאה, תקלה בייבוא רכיב ההערכה תוקנה, והבדיקות המקומיות בודקות התנהגויות אמיתיות. האפליקציה משתמשת במודלים שמורים.
אין לטעון שה־39.1% או ה־90.6% ההיסטוריים הם תוצאת מבחן עצמאי ששוחזר בסבב הזה.

## מה נדרש לתיקוף מדעי מלא

לאמת מקור וזמן לכל מאפיין, לקבע גרסת דאטה, לבנות פיצולי זמן, לכוון על validation בלבד, להקפיא בחירה, ולבדוק פעם אחת על תקופה נפרדת. זהו שינוי מחקרי ואימון מחדש, ולא פעולת ניקוי קוד.
